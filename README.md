# 樽見鉄道 GPS Sequencer

`tarumi-api` の `POST /api/position` を実際に呼び出し、GPS記録の再生位置から駅・トンネル・根尾川の情報を表示する、HTML / CSS / JavaScript + Vite のlocalhostアプリです。

## 起動

このディレクトリで実行します。Node.js 22.12以上（推奨: Node.js 24 LTS）が必要です。

```sh
npm ci
npm run dev
```

**http://127.0.0.1:5173/** をブラウザで開いてください。`http://localhost:5173/` でも開けます。

初期接続先は `http://localhost:8787/api/position` です。開発中はブラウザから同一オリジンの `/local-api/api/position` に送信し、Viteが `http://127.0.0.1:8787` へ転送します（[Viteのproxy設定](https://vite.dev/config/server-options#server-proxy)）。ブラウザからローカルAPIへのCORS事前リクエストは発生しません。APIが停止している場合は502で起動案内を表示します。公開APIやビルド後の接続は指定URLへ直接送信します。隣のAPIプロジェクトで `npm run data:local`、`npm run dev` を実行してください。
右上の設定を開き「公開APIに接続」を押すと公開Workerへ切り替わります。リロード時は必ずローカルに戻ります。以前の保存URLや環境変数で公開APIに自動接続しません。

GPS記録の `speed` を位置に合わせて補間し、km/hで表示します（再生倍率とは別です）。駅付近で0.8m/s以下が10秒以上続く区間を停車候補とし、最初の区間を到着として、停車中は0秒を保持します。GPSノイズによる推定誤差はあります。

## 操作

- 往路／復路を切り替えると、その方向のGPS記録の先頭へ戻ります。
- 再生／一時停止、0.5〜16倍速、10秒単位のスキップ、前／次の駅へのジャンプ。
- シークバーをドラッグして任意の時刻へ移動。上の駅名や地図の駅をクリックしても移動できます。
- 地図の全体表示、拡大／縮小、現在地の追従。地図をドラッグすると追従を解除します。
- キーボード: Spaceで再生／一時停止、左右キーで10秒移動（入力欄・ボタン等にフォーカスがあるときは通常のキー操作を優先）。
- APIの接続バッジまたは設定ボタンから、送信JSON・応答JSON・送信回数・応答時間を確認できます。
- タブを非表示にすると一時停止します。
- トンネル内では地図・予測表示・再生コントロールをダークテーマに切り替え、出口通過でライトテーマに戻します。API応答の間も補間したトンネル判定に連動します。

## データと時刻

元データは `data/gps-front.json` / `data/gps-back.json`。起動時とビルド時に `public/data/` へ同期します。GPSを差し替えた場合は開発サーバーを再起動してください。

| 方向 | 点数 | シーク範囲（元ファイルの t） | 記録の範囲 |
| --- | ---: | --- | --- |
| 往路 front | 1,793 | 419〜2,211秒 / 06:59〜36:51 | 木知原の手前〜樽見 |
| 復路 back | 1,739 | 3〜1,741秒 / 00:03〜29:01 | 樽見〜織部付近 |

`records[].t` は映像に同期済みの秒数です。シークではこの秒数を維持し、GPSがない映像区間へは移動しません。GPS時刻は `meta.start_time + t + meta.offset` から復元し、`recordedAt` にISO日時で送信します。画面には日本時間を表示します。`meta.gps.gps_start/end` は元GPSログの範囲なので、映像で切り取られた再生区間と一致するとは限りません。

位置はGPSの点間を補間し、時間は実際の経過時間に再生倍率を掛けて進めます。5秒を超えるGPS欠損では位置を捏造せず直前の点を保持し、API送信を停止します。入力の `speed` は単位が確定していないため距離・時間の予測に使いません。

駅・川・トンネルの元データは `../tarumi-api/data/` からコピーした `public/data/stations.json`、`neo_river_points.csv`、`tarumi_tunnels.csv` です。アプリの実行・ビルドは隣のAPIプロジェクトへ依存しません。`scripts/prepare-data.mjs` はAPIと同じ処理で駅・トンネルのシーク位置とグラフを生成し、同じデータハッシュを付けます。APIと地図のバージョンが違う場合、右下のデータ番号が黄褐色になります。

## APIと表示の意味

```json
{
  "latitude": 35.514371,
  "longitude": 136.653235,
  "direction": "front",
  "recordedAt": "2026-07-17T03:53:56.000Z"
}
```

- 予測の基準値はAPI応答を使用し、応答の間は以下の方法で補間します。APIエラー時は予測表示を消し、GPS記録の地図は操作できます。API未接続時にローカルの予測で代用することはありません。
- 通常再生中は応答完了から実時間で5秒待って次を送信し、未完了リクエストは1件までです。再生倍率を変えても待ち時間は実時間の5秒です。初回・シーク・方向切替・手動再接続では周期をリセットして取り直します。一時停止では予約済みの定期送信を取り消します。シーク後は140ms待って最後の位置を送信し、前の応答を破棄します。接続タイムアウトは再試行を含めて8秒です。ローカル位置予測APIで `Network connection lost` などの一時的な通信切断が起きた場合のみ、300ms待って同じGPSを1回再送します。位置予測は読み取り処理で、公開API・入力エラー・データ未登録エラーは再試行しません。Wranglerの[5秒周期の接続切断報告](https://github.com/cloudflare/workers-sdk/issues/14641)への対策として、送信開始時刻からの固定周期を避けています。
- API応答の間は、取得時の予測秒数から経過した再生秒数を引いてカウントダウンします。4倍速では1実秒で4秒減り、一時停止では止まります。APIの前方イベント一覧から通過済みのイベントを外し、次の駅・トンネルへ進めます。駅・トンネルまでの距離は、その間にGPS軌跡に沿って移動した距離を差し引きます。
- 次の駅の時間は同方向の走行記録に基づく、GPSから推定した停車開始までの参考値（停車未検出時は駅座標）です。運行ダイヤや正式な到着予測ではありません。停車中の同じGPSから停車経過時間は判定できません。
- トンネル内の場合は入口ではなく出口を表示します。GPS軌跡へ投影して判定するため、GPS欠損中の実際の位置の推測は行いません。
- 川との距離は `river.distanceMeters` / `signedDistanceMeters`（線路に直交する横方向）です。東は＋、西は−。`next.river` は前方の川中心線交差点までの走行距離なので別物です。
- 川の横方向距離は、APIと地図のデータバージョンが一致する場合、現在のGPS位置と川の線形から再計算します。バージョンが違う場合は取得時の距離を維持し、その旨を表示します。
- 川のグラフの線は全記録を10秒間隔で計算したローカル参照値、赤点はAPI応答およびその間のGPS補間、赤い縦線は現在の再生時刻です。上下表示範囲を超える値は端へ表示し、交点がない区間は線を切ります。表示範囲はグラフのツールチップで確認できます。
- 本巣・織部など選択した方向の記録範囲外の駅は薄く表示し、ジャンプできません。駅間の線路を想像で補いません。

## 配色

基本色は白 `#ffffff`（ground）、緑 `#18ff14`（操作・路線）、茶 `#331e19`（empty）、黒 `#000000`（文字）です。トンネル内は茶背景・白文字へ切り替えます。境界線や補助レイヤーは基本色の透明度で調整しています。

## 地図の設定

Mapbox GL JS + Mapbox Standard を使用しています。駅・走行軌跡・川・トンネルは独自GeoJSONとマーカーで重ね、トンネル内では背景地図も night に切り替えます。画面は地図の右に「次の駅 → トンネル → 川との距離」の順に表示し、スマートフォンでは縦に並びます。

`.env.local` に `VITE_MAPBOX_ACCESS_TOKEN=pk.…` を設定して `npm run dev` を起動してください。変更時は開発サーバーを再起動します。`.env.local` はGit管理対象外です。公開トークンはブラウザから参照されるため、Mapbox側で利用URLを制限してください。GitHub Pagesへのビルドでも同じ環境変数が必要です。

地図利用はMapboxの料金体系に従います。[料金](https://www.mapbox.com/pricing)・[課金単位](https://docs.mapbox.com/mapbox-gl-js/guides/pricing/)を参照してください。低コストな代替はMapLibre + 地理院タイルですが、現在はご指定のMapboxを採用しています。地図のロゴと出典表示は保持しています。

## 検証とビルド

```sh
npm test            # 時刻変換・補間・終端停止・方向切替時の応答競合・APIエラー
npm run test:browser # Google Chromeで実API・地図・再生・シーク・トンネル・モバイル表示を検証
npm run build       # dist/ に静的出力
npm run preview     # http://127.0.0.1:4173/ でビルド結果を確認
```

ブラウザ検証はGoogle Chromeがインストールされた環境を想定します。ローカルAPIを起動してから実行してください。ビルドは静的ファイルのみを生成します。このアプリ自身のサーバーやD1設定は不要です。

主なファイル: `index.html`（画面）、`src/style.css`（デザイン）、`src/main.js`（画面・地図・再生）、`src/timeline.js`（GPS時刻・補間）、`src/api.js`（API送信制御）、`scripts/prepare-data.mjs`（地図・グラフ生成）。

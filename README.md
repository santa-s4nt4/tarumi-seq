# 樽見OTO鉄道

2026-11-21の機能修正依頼①・②に合わせ、トップのタブ付きメニューからLIVE／CUSTOMへ進む構成です。LIVEとCUSTOMは同梱ダイヤから列車位置と駅・トンネルの合図を計算します。実機GPSによる補正は開発専用のPERFORMANCEにまとめています。

## 起動

Node.js 22.12以上で、このディレクトリから実行します。

```sh
npm ci
npm run dev
```

http://localhost:5173/ を開きます。地図には `.env.local` の `VITE_MAPBOX_ACCESS_TOKEN` を使用します。設定されていない場合や地図を読み込めない場合は、同梱の簡易路線図を表示します。LIVE／CUSTOMのダイヤ再生にはAPIは不要です。

## 画面と操作

| URL | 内容 |
| --- | --- |
| `/` | 北を上にした本巣〜樽見の概要図と、LIVE／CUSTOMを選ぶメニュー |
| `/live/` | 本巣〜樽見を走る列車のうち、運行中の列車から選択し、OKで追従。速度の下に日本時間の現在時刻 |
| `/custom/` | 平日／土・休日、方面、発車駅・ダイヤを選んで再生。速度の下に再生時刻 |
| `/performance/` | 開発専用。スマホのQR連携、乗車GPSによる遅延補正、iPadとの画面共有 |
| `/console/` | 開発専用。記録GPSの再生と位置APIの診断 |

LIVEは運行中の列車、CUSTOMは運行日・方面で絞ったダイヤを縦の一覧から選び、OKで移動します。モードタブは緑の太い下線で選択中を示します。メニューはPCでは右、スマホでは上に表示されます。トップの選択メニューには閉じるボタンがなく、Escapeでも閉じません。OKでは地図を読み込み直さず、約1.8秒のイージングで選択した列車へ寄ります。LIVE／CUSTOMから開いた場合も約1.8秒で概要図へ引き、閲覧していた列車の位置と時刻だけを残します。メニュー自体は420msで動き、×／Escapeでも同じ地図のまま元の視点へ戻ります。CUSTOMのシークバーは280msで下へ隠れてからメニューを開き、メニューが閉じた後に下から現れます。再生中に開くと一時停止し、地図の復帰後に再開します。OSの「動きを減らす」設定ではこれらの移動を省略します。

概要図は本巣〜樽見の11駅と区間内の列車を表示します。列車は路線上の緑の丸で示し、ホバー／キーボードフォーカスで「樽見発 21:47–22:55」のように発車駅とダイヤを表示します。クリックでメニューの列車を選択できます。駅名はPCではローマ字を併記、スマホでは漢字のみとし、樽見・本巣を他駅より大きく表示します。根尾川は薄い水色で示し、橋梁・トンネルの描画は省略します。LIVE一覧とCUSTOMのダイヤ選択は、本巣〜樽見を走る22列車に限定しています。大垣からの直通列車も対象に含み、大垣〜本巣だけを走る列車は除外します。対象外の列車の古いURLは選択メニューを開きます。

CUSTOMの下部には選択列車の全停車駅の目盛りを表示します。スマホでは横向きも含めてシークバー全体を画面幅に収め、横スクロールは行わず、選択範囲の開始駅・終了駅だけ名前を表示します。PCの駅名表示と配置は従来どおりです。シークバーのトンネル凡例は表示せず、トンネルの位置表示はPCのみとしています。IN／OUTをドラッグすると駅に吸着し、開始駅の発車から終了駅の到着までを再生します。マーカーは矢印キー・Home・Endでも操作でき、前後関係を越えません。OUTで停止し、もう一度再生するとINから始まります。駅へのジャンプ、10秒戻し・送り、シークにも対応します。区間はURLの `from` / `to` に保存され、再読み込みや共有後も復元されます。タブを隠すと一時停止します。

視点はLIVEが「自動／進行方向／鳥瞰」、CUSTOMはこれに「車窓」を追加します。進行方向の基本ズームは20、鳥瞰は19です。地形との衝突を避ける必要がある区間だけカメラ距離を広げます。車窓は既存の方向別YouTube映像で、ダイヤの再生位置との同期は行いません。

駅・トンネルの合図を直近3件表示し、トンネルの入口・出口の最後の10秒だけ大きなカウントダウンに切り替えます。停車中は速度0・到着駅の秒数0を維持し、後続の秒数を固定します。トンネル内はダークテーマです。走行ビューでは河川・橋梁・トンネルの凡例が右下にあります。駅の丸マーク内に文字は入れず、駅名のホバー下線も表示しません。トンネルの入口・出口ラベルは、地形の読み込みや視点変更に合わせて高さを補正し、トンネル端に固定します。

旧 `/que/` と `/live/?mode=playback` は `/custom/` へ移動し、列車・運行日・区間を引き継ぎます。公開版の旧Console URLはトップへ戻ります。公開ビルドにConsoleの画面本体やPERFORMANCE・GPS送信の実装は含めません。

## PERFORMANCEとiPad

隣の `tarumi-api` で `npm run dev` を起動します。起動時にローカルD1のマイグレーションと最新の記録GPS登録が実行されます。スマホ・iPadはPCと同じWi-Fiに接続し、このプロジェクトで通常の開発サーバーに加えて次を起動します。

```sh
npm run dev:phone
```

PCの http://localhost:5173/performance/ にQRモーダルが出ます。スマホがリンクを開くとPCは地図へ進みます。GPS取得はスマホで「GPSを送信する」を押してから開始します。画面を隠すと測位を一時停止するため、再開時に送信ボタンを押してください。

初回はターミナルに表示される `tarumi-phone-ca.crt` をスマホに渡し、CA証明書として信頼してください。iOSではプロファイルのインストール後、「設定 → 一般 → 情報 → 証明書信頼設定」で有効にします。QRの送信先はLANのHTTPS・5174番です。IPを固定する場合は両サーバーで同じ `TARUMI_PHONE_IP` を設定してください。

QRモーダルの「接続リンク・iPadで見る」に、LANのHTTP・5173番を使う閲覧リンクがあります。このリンクをiPadで開くと、PCの選択列車・遅延補正・視点を共有します。iPadは閲覧用です。GPS送信の鍵はiPadのリンクに含めません。リンクの鍵はURLのフラグメントに置き、認証時にAuthorizationヘッダーで送ります。有効期間は2時間です。

GPSが新鮮で精度50m以内・路線から100m以内、かつ候補が明確な場合に列車を自動選択します。交差・精度不足などで判別できない場合はPCで乗車列車を選択します。遅延補正は屋外の複数の測位で確認し、カウントダウンの最後の10秒・トンネル内では変更しません。スマホが送信を終了するとリンクは失効します。PCのメニューでQRへ戻った場合、再スキャンすると地図に戻ります。

## データと地図

ダイヤは既存の `public/data/timetable-reference.json`（2024年4月8日改正、19駅・44列車）です。今回の変更で公式ダイヤの再取得は行っていません。LIVEの位置・速度はこのダイヤによる推定で、運行会社のリアルタイム位置ではありません。未掲載の途中駅到着は発車30秒前、駅間は加減速と巡航を組み合わせた推定走行です。

路線は `public/data/railway-route.json` のOpenStreetMap由来の全線形状・9トンネル・23橋梁を使用します。線路高は国土地理院由来の19駅周辺標高を補間した表示用の値で、橋桁高の実測値ではありません。地形・線路・橋・マーカー・カメラで標高の単位をメートルに統一し、以前の地形1.5倍との不一致を解消しました。河川との交点が橋梁区間に収まることをテストしています。

カメラは現在地の線路標高を中心に追従します。自動視点は常に同じ進行方向カメラを仮定して地形の遮蔽を調べます。鳥瞰に切り替わった後の見え方を判定へ戻さず、遮蔽0.6秒・開通3秒の継続条件と最短保持時間で往復を防ぎます。

## Consoleと位置API

Consoleは `src/console.html` と `src/main.js` を開発時だけ読み込みます。記録GPSの元データは `data/gps-front.json` / `data/gps-back.json` です。起動・ビルド時に `public/data/` に同期します。記録を更新した場合は `npm run api:sync-local` で隣のAPIにも反映できます。

初期接続先は `http://localhost:8787/api/position` で、Viteの同一オリジン `/local-api` プロキシ経由で送ります。APIへの送信は `latitude` / `longitude` / `direction` / `recordedAt` / `datasetVersion`。GPS時刻は `meta.start_time + t + meta.offset` から復元します。5秒を超えるGPS欠損では位置を保持し、送信を止めます。

APIと画面のデータ世代が違う場合は409で案内し、実際のルート外の422と区別します。APIエラー時は予測を消し、ローカルの推定で代用しません。記録の再生・一時停止・倍速・シーク・方向切替・生リクエスト／レスポンスの確認はConsoleに残しています。

## 検証・ビルド・公開

```sh
npm test                 # 計算・範囲・カメラ・GPS・橋梁形状
npm run test:browser     # Chrome、ローカルAPI、実Mapboxを使う画面検証
npm run test:production  # /tarumi-seq/配下の公開ビルドと開発専用画面の除外
npm run build
npm run preview
```

ブラウザテストはGoogle ChromeとローカルAPIを起動した環境を使用します。旧QUE／LIVE再生専用UIのテストは、トップモーダル・CUSTOM・PERFORMANCEのテストへ置き換えています。既存ConsoleのAPI・再生・モバイルテストは維持しています。

GitHub Pagesは `.github/workflows/pages.yml` が `main` へのpushを受けてビルド・公開します。リポジトリのPages設定をGitHub Actionsにし、Actions secret `VITE_MAPBOX_ACCESS_TOKEN` を登録してください。ワークフローはPagesの接頭辞でビルドします。`/`、`/live/`、`/custom/`、旧URL用 `/que/` と `/console/` を出力します。`/performance/` は出力しません。

公開と同じパス構成をローカルで確認する場合:

```sh
npm run build -- --base=/tarumi-seq/
npm run preview -- --base=/tarumi-seq/
```

http://127.0.0.1:4173/tarumi-seq/ を開きます。通常のルート構成に戻す場合は `npm run build` を実行します。

主な実装: `src/entry.js`（ルート）、`src/experience.js` / `src/experience.css`（共通画面）、`src/mode-menu.js`（トップモーダル）、`src/station-timeline.js`（駅とIN／OUT）、`src/journey.js`（運行・区間）、`src/journey-map.js` / `src/journey-camera.js`（地図と視点）、`src/performance-link.js`（ローカルQR・共有）、`src/phone-sender.js`（スマホGPS送信）。

# 樽見鉄道 GPS Sequencer

`tarumi-api` の `POST /api/position` を実際に呼び出し、GPS記録の再生位置から駅・トンネル・根尾川の情報を表示する、HTML / CSS / JavaScript + Vite のアプリです。

## 起動

このディレクトリで実行します。Node.js 22.12以上（推奨: Node.js 24 LTS）が必要です。

```sh
npm ci
npm run dev
```

**http://127.0.0.1:5173/** をブラウザで開いてください。`http://localhost:5173/` でも開けます。

初期接続先は公開API `https://tarumi-api.santanaruse.workers.dev/api/position` です。右上の設定からURLを変更すると、その選択をブラウザーに保存します。ローカルAPIを使う場合は「ローカルURLを入力」→「接続する」を押し、隣のAPIプロジェクトで `npm run data:local`、`npm run dev` を実行してください。開発中のローカルAPI接続はViteの `/local-api/api/position` プロキシを通します（[Viteのproxy設定](https://vite.dev/config/server-options#server-proxy)）。公開APIやビルド後の接続は指定URLへ直接送信します。

GPS記録の `speed` を位置に合わせて補間し、km/hで表示します（再生倍率とは別です）。駅付近で0.8m/s以下が10秒以上続く区間を停車候補とし、最初の区間を到着として、停車中は0秒を保持します。GPSノイズによる推定誤差はあります。

## 操作

- 往路／復路を切り替えると、その方向のGPS記録の先頭へ戻ります。
- 再生／一時停止、0.5〜16倍速、10秒単位のスキップ、前／次の駅へのジャンプ。
- シークバーをドラッグして任意の時刻へ移動。上の駅名や地図の駅をクリックしても移動できます。
- 地図の全体表示、拡大／縮小、現在地の追従。地図をドラッグすると追従を解除します。
- キーボード: Spaceで再生／一時停止、左右キーで10秒移動（入力欄・ボタン等にフォーカスがあるときは通常のキー操作を優先）。
- APIの接続バッジまたは設定ボタンから、送信JSON・応答JSON・送信回数・応答時間を確認できます。
- タブを非表示にすると一時停止します。
- トンネル内では地図・予測表示・再生コントロールをダークテーマに切り替え、出口通過でライトテーマに戻します。API応答の間も補間したトンネル判定に連動します。

## データと時刻

`/que` の「ダイヤで再生」から、方面・平日／土曜休日・出発駅・発車時刻を選択し、「この列車で再生」で時刻表に合わせたシミュレーションを開始できます。対象は **本巣（TR09）〜樽見（TR19）の11駅** です。下りは本巣07:45発→樽見08:19着など、上りは樽見→本巣を再生します。途中駅からの出発、再生／停止、倍速、時刻へのシーク、駅へのジャンプが使えます。シミュレーション中は実際の時刻（例: 07:45:00）を表示し、同じ選択画面の「GPS記録に戻る」で従来の再生へ戻ります。

時刻表は添付と同じ[2024年4月8日改正の公式PDF](https://tarumi-railway.com/pdf/station_timetable/file/3)から本巣〜樽見だけを読み取った `public/data/timetable.json`（下り11・上り11の22列車、242駅発着）です。この区間の列車は平日・土曜休日共通です。本巣止まりの南側の列車・休日限定1001／1002列車は含めません。21・23列車の本巣駅での乗り換えを案内します。1036列車は本巣19:44着で再生を終了し、36列車への継続は行いません。

掲載された発車時刻、本巣駅の到着時刻、終点到着時刻はそのまま使います。未掲載の途中駅到着は発車30秒前とし、選択画面で `*` の推定表示を付けます。駅間は短い加減速と巡航を組み合わせた推定走行です。停車中は現在地と速度0を保持し、UP NEXTの他カードの秒数を固定します。シミュレーションの予測は選択したダイヤから求め、記録旅行のETAを返す位置APIへの送信は停止します。速度カードにも「推定速度」と明記します。

地理形状は[OpenStreetMapの樽見鉄道樽見線](https://www.openstreetmap.org/relation/1864491)を駅順に結んだ `public/data/railway-route.json`（全線約34.65km・9トンネル・本線の鉄橋23区間）から、選択した出発駅〜本巣または樽見の区間を使用します。鉄橋は同relationの `bridge=*` が付いた線路wayから抽出し、キュー画面では茶色の線（トンネル内は白）で示します。データは同梱しており、通常の起動・ビルドで外部から再取得しません。更新用の `scripts/import-timetable.py` は公式PDF（pdfplumberが必要）から本巣〜樽見の区間を抽出し、`scripts/import-railway.py` はOSM relation 1864491のfull XMLを入力に受け取ります。

線路の描画標高は[国土地理院の標高API](https://maps.gsi.go.jp/development/elevation_s.html)で取得した19駅周辺の地表高を起点に、駅間を線形補間しています。本巣駅付近を約38.7m、樽見駅付近を約168.4mとする緩やかなプロファイルで、トンネル区間でも山の地表をなぞりません。地形は従来どおり立体表示し、地形の手前に出る線路と山に隠れる線路を描き分けます。駅周辺標高は国土地理院の標高データを加工した**表示用の推定値**で、実測の線路高や橋桁高ではありません。

キュー画面ではGPSの現在地を表示時だけOSMの線路へ投影し、通過済み区間もその線路上で色分けします。これで鉄橋・トンネルの線と現在地がずれずに重なります。位置予測APIへ送るGPS座標は変更しません。

元データは `data/gps-front.json` / `data/gps-back.json`。起動時とビルド時に `public/data/` へ同期します。GPSを差し替えた場合は開発サーバーを再起動してください。

| 方向 | 点数 | シーク範囲（元ファイルの t） | 記録の範囲 |
| --- | ---: | --- | --- |
| 往路 front | 1,793 | 419〜2,211秒 / 06:59〜36:51 | 木知原の手前〜樽見 |
| 復路 back | 1,739 | 3〜1,741秒 / 00:03〜29:01 | 樽見〜織部付近 |

`records[].t` は映像に同期済みの秒数です。シークではこの秒数を維持し、GPSがない映像区間へは移動しません。GPS時刻は `meta.start_time + t + meta.offset` から復元し、`recordedAt` にISO日時で送信します。画面には日本時間を表示します。`meta.gps.gps_start/end` は元GPSログの範囲なので、映像で切り取られた再生区間と一致するとは限りません。

位置はGPSの点間を補間し、時間は実際の経過時間に再生倍率を掛けて進めます。5秒を超えるGPS欠損では位置を捏造せず直前の点を保持し、API送信を停止します。入力の `speed` は単位が確定していないため距離・時間の予測に使いません。

駅・川・トンネルの元データは `../tarumi-api/data/` からコピーした `public/data/stations.json`、`neo_river_points.csv`、`tarumi_tunnels.csv` です。アプリの実行・ビルドは隣のAPIプロジェクトへ依存しません。`scripts/prepare-data.mjs` はAPIと同じ処理で駅・トンネルのシーク位置とグラフを生成し、同じデータハッシュを付けます。APIと地図のバージョンが違う場合、右下のデータ番号が黄褐色になります。

## APIと表示の意味

```json
{
  "latitude": 35.514371,
  "longitude": 136.653235,
  "direction": "front",
  "recordedAt": "2026-07-17T03:53:56.000Z"
}
```

- 予測の基準値はAPI応答を使用し、応答の間は以下の方法で補間します。APIエラー時は予測表示を消し、GPS記録の地図は操作できます。API未接続時にローカルの予測で代用することはありません。
- 通常再生中は応答完了から実時間で5秒待って次を送信し、未完了リクエストは1件までです。再生倍率を変えても待ち時間は実時間の5秒です。初回・シーク・方向切替・手動再接続では周期をリセットして取り直します。一時停止では予約済みの定期送信を取り消します。シーク後は140ms待って最後の位置を送信し、前の応答を破棄します。接続タイムアウトは再試行を含めて8秒です。ローカル位置予測APIで `Network connection lost` などの一時的な通信切断が起きた場合のみ、300ms待って同じGPSを1回再送します。位置予測は読み取り処理で、公開API・入力エラー・データ未登録エラーは再試行しません。Wranglerの[5秒周期の接続切断報告](https://github.com/cloudflare/workers-sdk/issues/14641)への対策として、送信開始時刻からの固定周期を避けています。
- API応答の間は、取得時の予測秒数から経過した再生秒数を引いてカウントダウンします。4倍速では1実秒で4秒減り、一時停止では止まります。APIの前方イベント一覧から通過済みのイベントを外し、次の駅・トンネルへ進めます。駅・トンネルまでの距離は、その間にGPS軌跡に沿って移動した距離を差し引きます。
- 次の駅の時間は同方向の走行記録に基づく、GPSから推定した停車開始までの参考値（停車未検出時は駅座標）です。運行ダイヤや正式な到着予測ではありません。停車中の同じGPSから停車経過時間は判定できません。
- トンネル内の場合は入口ではなく出口を表示します。GPS軌跡へ投影して判定するため、GPS欠損中の実際の位置の推測は行いません。
- 川との距離は `river.distanceMeters` / `signedDistanceMeters`（線路に直交する横方向）です。東は＋、西は−。`next.river` は前方の川中心線交差点までの走行距離なので別物です。
- 川の横方向距離は、APIと地図のデータバージョンが一致する場合、現在のGPS位置と川の線形から再計算します。バージョンが違う場合は取得時の距離を維持し、その旨を表示します。
- 川のグラフの線は全記録を10秒間隔で計算したローカル参照値、赤点はAPI応答およびその間のGPS補間、赤い縦線は現在の再生時刻です。上下表示範囲を超える値は端へ表示し、交点がない区間は線を切ります。表示範囲はグラフのツールチップで確認できます。
- 本巣・織部など選択した方向の記録範囲外の駅は薄く表示し、ジャンプできません。駅間の線路を想像で補いません。

## 配色

`/que` は `../tarumi-oto-fes-main` のブランドに準拠しています。専用書体 **Tarumi OTO Stroke**、白 `#ffffff`、緑 `#00ff36`、黒 `#000000` を基本に、根尾川は青 `#0a84ff`、地形は平野 `#c4c1b0` と森 `#1d3a22` を使用します。トンネル内は黒背景・白文字に切り替わり、緑は維持します。大きな秒数、四角い面、緑の罫線で次の合図を表示します。

書体は `public/fonts/TarumiOTOStroke-Regular.otf`、ロゴは `public/logos/header-logo.svg` に参照元の実ファイルを同梱しています。SVG・ICO favicon と Apple touch icon も同じサイトから取り込んでおり、実行時に隣のプロジェクトへ依存しません。ブランド資産が更新された場合は、これらのファイルも同期してください。キュー専用のスタイルは `src/que.css` です。

スマートフォンではキューを地図の下側に置き、その上の地図領域へ現在地を追従させます。速度と凡例は上部、再生とシークは画面下部に表示します。倍率・ダイヤ選択・接続設定にも同じ書体と配色を適用しています。

コンソールの基本色は従来どおり白 `#ffffff`、緑 `#18ff14`、黒系 `#0b0e12`、黒 `#000000` です。書体は `/`・`/console` も **Tarumi OTO Stroke** に統一しています。ヘッダーのロゴとブラウザーアイコンもキューと共通です。

## 地図の設定

Mapbox GL JS + Mapbox Standard を使用しています。駅・走行軌跡・川・トンネルは独自GeoJSONとマーカーで重ね、トンネル内では背景地図も night に切り替えます。画面は地図の右に「次の駅 → トンネル → 川との距離」の順に表示し、スマートフォンでは縦に並びます。

`.env.local` に `VITE_MAPBOX_ACCESS_TOKEN=pk.…` を設定して `npm run dev` を起動してください。変更時は開発サーバーを再起動します。`.env.local` はGit管理対象外です。公開トークンはブラウザから参照されるため、Mapbox側で利用URLを制限してください。GitHub Pagesへのビルドでも同じ環境変数が必要です。

地図利用はMapboxの料金体系に従います。[料金](https://www.mapbox.com/pricing)・[課金単位](https://docs.mapbox.com/mapbox-gl-js/guides/pricing/)を参照してください。低コストな代替はMapLibre + 地理院タイルですが、現在はご指定のMapboxを採用しています。地図のロゴと出典表示は保持しています。

## GitHub Pagesで公開する

`.github/workflows/pages.yml` を追加しています。`main` へのpushで、テスト・Viteのビルド・`dist/` の公開を実行します。GitHub Pagesの公開先からURLの接頭辞を取得し、JavaScript・CSS・データ・画面切り替えを同じ接頭辞に揃えます。`/que/` と `/console/` は専用のHTMLを出力するため、直接開く・リロードする操作にも対応します。

1. [このリポジトリのSettings → Pages](https://github.com/santa-s4nt4/tarumi-seq/settings/pages) を開き、**Build and deployment → Source → GitHub Actions** を選びます。
2. Mapboxで `pk.` から始まる公開アクセストークンを用意します。利用URLを制限している場合は `https://santa-s4nt4.github.io` を許可します。ドメインを変える場合はそのURLも許可してください（[MapboxのURL制限](https://docs.mapbox.com/accounts/guides/tokens/#url-restrictions)）。
3. GitHubの **Settings → Secrets and variables → Actions → New repository secret** で、名前を **`VITE_MAPBOX_ACCESS_TOKEN`**、値をそのトークンとして登録します。ローカルの `.env.local` はGitHub Actionsには渡らないため、別途この登録が必要です。
4. この `tarumi-seq` ディレクトリで変更をcommitし、`main` にpushします。

   ```sh
   git add .
   git commit -m "Limit simulation to Motosu–Tarumi and prepare GitHub Pages"
   git push origin main
   ```

5. GitHubの **Actions → Deploy GitHub Pages** が成功したら、キュー画面を **https://santa-s4nt4.github.io/tarumi-seq/que/** で開きます。コンソールは **https://santa-s4nt4.github.io/tarumi-seq/console/** です。設定後の再実行には **Actions → Deploy GitHub Pages → Run workflow** も使えます。

ダイヤ再生は同梱データで動くため、位置APIの起動は不要です。GPS記録のキューは初期設定で公開APIへ接続します。GitHub PagesにはViteのローカルAPIプロキシはありません。公開APIはPagesからのCORS事前リクエストに対応しています。

リポジトリ名やGitHubアカウント名を変えた場合は、上のURLを置き換えてください。ビルドの接頭辞はワークフローが自動で取得します。独自ドメインをPagesに設定した場合も、取得した接頭辞でビルドします。

公開前にローカルで同じURL構成を確認できます。

```sh
npm run build -- --base=/tarumi-seq/
npm run preview
```

**http://127.0.0.1:4173/tarumi-seq/que/** を開いて確認してください。通常のルートURLでビルドし直すには `npm run build` を実行します。設定の根拠は [GitHubのPagesワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) と [ViteのGitHub Pages公開手順](https://vite.dev/guide/static-deploy.html#github-pages)です。


## 画面のURL

- `/` と `/console`：従来のコンソール。API診断、駅・川・トンネルの予測、GPS再生を表示します。
- `/que`：キュー画面。立体地形に青い根尾川、ブランドの緑の通過前路線と薄い緑の通過済み路線、緑の現在地を表示し、駅・トンネルのチェックポイントを到着順に最大3件表示します。

両画面のヘッダーから切り替えられます。キューはAPI応答からGPS再生時刻で補間され、停止中は秒数も停止します。APIエラー時にはキューを消し、再接続ボタンを表示します。`/que` は現在地を自動追尾します。再生開始・シーク・往復切り替え時にも追尾を再開します。地図上の視点コントロールの「自動」「通常固定」「鳥瞰図固定」「動画」から視点を直接切り替えられます。「倍率」から通常ビューと鳥瞰図の近さを個別に＋／−で調整できます（ズーム14〜20、0.5刻み、鳥瞰図は通常ビュー以上）。固定モードでは山の遮りによる自動切り替えを行わず、シークや往復切り替え後も選んだ視点で追尾します。初期値は自動・通常19／鳥瞰図19で、設定はブラウザーに保存され、「初期値に戻す」で倍率のみリセットできます。設定変更も0.5秒で反映します。地図へのホイール・ドラッグ・ピンチ・回転操作は引き続き無効です。カメラは進行方向を正面に向け、カーブに合わせて滑らかに回転します。停車中は前方の軌跡、記録終端では直前の軌跡から向きを求めます。

UP NEXTは直近のチェックポイントを主カードにし、通過・発車すると次のカードを繰り上げます。トンネルは1本につき1枚で、「トンネルnまで」から「トンネルn通過まで」に同じカードの表示を切り替えます。駅／トンネルの大きなアイコンを秒数の横に表示し、デスクトップのカードは従来の約2倍の幅・文字サイズに拡大しています。小さい画面では主カードを横幅いっぱい、後続2枚を横並びにします。駅の表示が0秒の間は他のカードの秒数を保持し、API更新でも減らしません。発車後はGPS再生時刻に対応する残り秒数の更新を再開し、シーク・往復切り替えでは保持値をリセットします。

駅・トンネルの直近の合図が **10秒前〜到着直前** になると、地図中央に大きなカウントダウンを表示します。対象名（「○○駅まで」「トンネルnまで」「トンネルn通過まで」）と秒数を、半透明の背景と時計回りに進む目盛りで表示します。円の進捗は実際の残り秒数に連動し、一時停止・倍速・シークにも追従します。残り秒数は切り上げでキューのカードと揃えています。停車中の0秒では大きな表示を閉じ、APIエラー・往復切り替えでも古い表示を消します。動画モードでは表示しません。カウントダウン中は画面上端から地図を広げ、地図・巨大なカウントダウン・シークバーだけを表示します。ヘッダー、通常のキュー、速度、凡例、視点コントロール、再生ボタンを隠し、終了時に元へ戻します。PC・スマートフォンとも円を画面内に収めながら最大限大きく表示します。表示中もシークと Space による再生／停止が使えます。実装は `src/countdown.js` と `src/countdown.css` です。

立体地形は [Mapbox Terrain-DEM](https://docs.mapbox.com/mapbox-gl-js/example/add-terrain/) を使用し、通常は地形を見渡せるズーム19、カメラの傾きは通常72度、地形の高さ1.5倍に設定しています。Mapboxの利用には既存の `VITE_MAPBOX_ACCESS_TOKEN` を使います。WebGLまたはトークンが利用できない場合は簡易地図を表示します。ビルド時には `/console/` と `/que/` 用のHTMLも出力します。


ライト／ダークの切り替えは約 **0.9秒のフェード** で行います。UIの背景・文字・罫線を補間し、地図は切り替え直前の描画を一時的に重ねて新しいテーマへクロスフェードします。WebGLの描画時に必要な1フレームだけ取得するため、常時 `preserveDrawingBuffer` を有効にしません。連続シークで切り替え方向が変わっても現在の見え方から継続し、終了後の一時レイヤーを破棄します。OSの「視差効果を減らす」等（`prefers-reduced-motion`）が有効な場合はアニメーションを省略します。実装は `src/theme.js` と `src/theme.css` です。

`/que` の地形には Mapbox Terrain v2 の数値ラベルを省いた等高線、Terrain-DEM の陰影を重ねています。トンネル内ではUIを黒系、地形を起伏が見える暗い森の緑に切り替え、走行中のトンネル名を表示します。トンネル区間は茶色の縁取りを付けた緑の点線、入口・出口はポータルマークで示します。駅は「駅」マークと駅名のラベル、次の駅は緑のラベルで強調します。遠方のラベルの重なりを避けるため、駅マークは現在地から2.2km、トンネルマークは1.6km以内を表示します。

Mapboxロゴの上には、デスクトップでUP NEXTの主カードと同じ幅の走行速度カードを表示します。小さい画面では地図の見える範囲を保つため速度カードをコンパクトに表示します。速度はAPI/GPS補間の km/h 値を使い、API未接続時には未確定値 `—` を表示します。


`/que` の地図上のトンネル表記は名称だけにし、入口・出口の文字は表示しません。路線・トンネル・鉄橋は駅周辺標高から求めた線路プロファイルに沿って描き、地形に隠れた部分は通常の20%の不透明度（縁取りは10%）で薄く表示します。現在地、駅・トンネルのラベルとマークも同じ線路高へ置き、地形に隠れている場合は20%の不透明度になります。


`/que` の自動モードは初期値で通常ズーム19、傾き72度のパースで進行方向に合わせて追尾します。Mapboxが現在地を山の裏側として20%の不透明度にした場合、0.5秒のイージングで真上からの鳥瞰図（初期ズーム19）へ切り替えます。通常ビューでの実際のカメラ位置を保存し、地形への衝突を避けるMapboxの補正も含めた視線で復帰を判定します。DEMの判定には6mの余裕を設け、現在地と進行先300m（30m間隔）の視線が0.35秒連続で確実に開けた場合に、0.5秒で通常のパースへ戻します。短い隙間では鳥瞰図を維持し、標高データの未取得を「見える」と扱いません。移行中のマーカーの濃さも再切り替えの根拠にしません。停止中も切り替えと追尾を継続します。シーク・往復切り替えでは直前の遮り判定を引き継ぎません。現在地マーカーは山に隠れたとき20%、見えているときは通常の濃さで表示します。

追尾は描画フレームごとに更新し、方位は前方80mの軌跡から時間に基づいて滑らかに変えます。ズーム・傾きはモード切り替えで必要なときだけ変更し、Mapboxが地形への衝突を避けて補正したズームを毎フレーム戻しません。現在地・駅名・トンネルのDOM位置は地図の描画後に小数ピクセルで投影し、地図とラベルの描画時刻および丸めのずれを抑えています。

`/que` の現在地は緑色の円で表示します。視点が変わっても円形を保ち、山に隠れたときは20%の不透明度になります。簡易地図も円形のマーカーを使用します。

手前の山だけを非表示・半透明にして奥の地形を見せる機能は実装していません。現在使用しているMapboxの標準[terrain設定](https://docs.mapbox.com/style-spec/reference/terrain/)には地形を部分的に透明にする項目がなく、[clipレイヤー](https://docs.mapbox.com/mapbox-gl-js/example/clip-layer/)も地形の切り抜きには対応していません。地形の起伏と等高線は維持しています。


地図上の視点コントロールの **動画** を押すと、地図領域にYouTube動画をiframeで表示します。往路は [本巣→樽見](https://youtu.be/m-jjJKsWI24)、復路は [樽見→本巣](https://youtu.be/7O6dZcTG2mQ) に切り替わります。動画はキューと速度カードより上のレイヤーに表示します。動画の再生・停止・シークはYouTube側のコントロールで操作します（GPS／ダイヤ再生とは独立）。地図のモードへ戻すと動画を閉じます。選んだモードはブラウザーに保存されます。通常ズームの初期値を19へ変更したため、旧バージョンの保存ズームは初回に19へ更新します。

変更点の一覧と検証内容は [CHANGELOG.md](CHANGELOG.md) に記録しています。
